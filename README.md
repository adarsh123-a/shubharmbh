# Shubharambh Realty — Enterprise Real Estate & Land ERP

A full-stack, enterprise-grade multi-role ERP platform tailored for **Land & Plots (Zameen) Selling**, featuring 5 distinct role-based portals, tokenized plot bookings, free cab site visit dispatch, commission tracking, and platform audit logging.

---

## 🌟 Architecture & Role Hierarchy

The platform implements strict multi-tier Role-Based Access Control (RBAC):

```
Super-Admin (Enterprise Owner)
    │
    ├── Admin (Operations & Inventory Management)
    │     │
    │     └── RM — Relationship Manager (Customer Contact & Call Follow-up)
    │           │
    │           └── Agent (Customer Lead Generation & Commission Tracking)
    │
    └── Customer (Public Portal: Browse Land Schemes, Book Cab, Reserve Token)
```

### Core Role Responsibilities:
1. **Super-Admin**: Enterprise control, user CRUD & status toggle (Active/Suspended), land catalog publishing, live system audit activity feed.
2. **Admin**: Inventory management (Land schemes with Latitude/Longitude coordinates and plots in Gaj/Sq.Ft), RM team onboarding, plot booking final approval.
3. **RM (Relationship Manager)**: Dedicated lead contact desk. Receives leads generated by on-ground agents, initiates direct Call / WhatsApp, records discussion notes, schedules accompanied site visits, and reviews plot token bookings.
4. **Agent**: On-ground sales partner. Views available properties/plots inventory, tracks properties sold count, monitors percentage-based commission transaction history (e.g. 5% payout per plot sold), and adds customer leads with a 3-field form (Name, Email, Phone).
5. **Customer**: Public land scheme catalog, interactive plot selector, free site visit cab booking with live GPS directions.

## ⚙️ Installation & Local Setup

### Prerequisites:
- **Node.js**: v18.0.0 or higher
- **MongoDB**: Local MongoDB community server (v6.0+) or MongoDB Atlas URI

### 1. Backend Setup:
```bash
# Navigate to backend directory
cd backend

# Install dependencies
npm install

# Configure environment variables
cp .env.example .env
# Edit .env with your MongoDB URI and JWT Secret

# (Optional) Seed initial land schemes and admin users
npm run seed:properties

# Start development server
npm run dev
# Backend runs on http://localhost:5000
```

### 2. Frontend Setup:
```bash
# Navigate to customer portal (Vite root)
cd frontend/customer

# Install dependencies
npm install

# Start Vite development server
npm run dev
# Frontend runs on http://localhost:5173
```

| `MONGO_URI` | MongoDB connection string | `mongodb://127.0.0.1:27017/shubharambh_realty` |

## 📡 REST API Endpoints Guide

All protected endpoints accept authentication via **HTTP-only cookie (`token`)** or **Authorization header (`Bearer <token>`)**.

### 1. Authentication (`/api/auth`)
- `POST /api/auth/register` — Public registration (Customer / Agent signup)
- `POST /api/auth/login` — User authentication & JWT issuance
- `POST /api/auth/logout` — Clear session cookies
- `GET /api/auth/me` — Retrieve active authenticated user profile

### 2. Super-Admin Portal (`/api/super-admin`) — *Requires `super_admin` role*
- `GET /api/super-admin/dashboard` — Platform KPIs (total users, active inventory, pending actions)
- `GET /api/super-admin/users` — List all registered users across all roles
- `POST /api/super-admin/users` — Create any user with initial password
- `PATCH /api/super-admin/users/:id/status` — Toggle user status (`active` / `suspended`)
- `GET /api/super-admin/activities` — Real-time enterprise audit log

### 3. Admin Portal (`/api/admin`) — *Requires `admin` or `super_admin` role*
- `GET /api/admin/dashboard` — Operational KPIs and inventory overview
- `GET /api/admin/team` — View team hierarchy (RMs and their assigned Agents)
- `POST /api/admin/team/rm` — Onboard a new Relationship Manager (RM)
- `GET /api/admin/bookings` — Plot bookings awaiting final approval
- `PATCH /api/admin/bookings/:id/status` — Approve or reject plot token booking

### 4. RM Desk (`/api/rm`) — *Requires `rm`, `admin`, or `super_admin` role*
- `GET /api/rm/dashboard` — RM metrics (agent leads, managed agents, site visits, bookings)
- `GET /api/rm/customers` — Incoming customer leads added by agents
- `PATCH /api/rm/customers/:id` — Update lead status (`contacted`, `visit_scheduled`, `booked`, `lost`) and discussion notes
- `GET /api/rm/visits` — Scheduled accompanied site visits & cab requests
- `PATCH /api/rm/visits/:id` — Assign driver/cab and mark visit completed
- `GET /api/rm/agents` — List on-ground agents managed by this RM
- `POST /api/rm/agents` — Onboard a new agent under RM's team
- `GET /api/rm/bookings` — Review plot token submissions from agents
- `PATCH /api/rm/bookings/:id/review` — Forward booking to Admin or reject

### 5. Agent Portal (`/api/agent`) — *Requires `agent`, `rm`, `admin`, or `super_admin` role*
- `GET /api/agent/dashboard` — Personal performance (Properties sold count, commission earned)
- `GET /api/agent/customers` — View customer leads submitted by this agent
- `POST /api/agent/customers` — **Add Customer Lead** (Strictly 3 fields: `name`, `email`, `phone`)
- `GET /api/agent/bookings` — Sold properties & percentage-based commission transaction history
- `POST /api/agent/bookings` — Submit plot token booking request

### 6. Properties & Land Catalog (`/api/properties`)
- `GET /api/properties` — List all land schemes, coordinates, plot availability, rate per गज
- `GET /api/properties/:id` — Fetch scheme details and plot layout grid
- `POST /api/properties` — Create new land scheme (Admin / Super Admin only)
- `PUT /api/properties/:landId` — Update land scheme details, rate, coordinates, or status (*Super-Admin only*)
- `DELETE /api/properties/:landId` — Permanently delete land scheme from catalog (*Super-Admin only*)

## 🚀 Production Deployment Guide

### Deploying Frontend (Vercel / Netlify / VPS):
```bash
# 1. Build the frontend
cd frontend/customer
npm run build

# 2. Output directory is located at:
# frontend/dist
# Configure your hosting provider's build output directory to: frontend/dist
```

### Deploying Backend (Render / Railway / Ubuntu VPS):
1. Set the Root Directory to `backend/`.
2. Build Command: `npm install`
3. Start Command: `npm start` (runs `node server.js`).
4. Set Environment Variables:
   - `MONGO_URI`: Production MongoDB Atlas connection string.
   - `JWT_SECRET`: High-entropy secret key.
   - `NODE_ENV`: `production`
   - `CLIENT_URL`: Your production frontend domain (e.g. `https://shubharambhrealty.com`).
